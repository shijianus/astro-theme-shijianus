## 1. 序言：為什麼在 2026 年依然堅持寫獨立博客？

在演算法推薦、短影音與封閉社群平台徹底主導資訊流動的今天，搭建並維護一個獨立的個人博客，常被視為一種「過時」或「低效」的極客執念。

然而，現實卻反覆印證著另一種危機：
1. **數據所有權的剝離**：你的文章、筆記與思考被封裝在不同商業公司的封閉花園中，隨時面臨演算法降權、內容被刪除或帳號停用的風險；
2. **閱讀深度的消解**：為了迎合推薦系統的點擊率，資訊被切割成零碎的情緒碎片，缺乏上下文、缺乏版本修訂歷史，更缺乏體系化的推演；
3. **介面表達的同質化**：所有創作者都在使用相同的幾套模板與版式，作者個人的審美品味、技術判斷與工程執念被無情抹平。

**EpoCanvas（以及 shijianus.us）正是在這樣的背景下誕生的。**

我需要一個屬於自己的**數位花園（Digital Garden）**：它擁有獨立的域名、自主掌控的原始碼、乾淨開放的資料格式（Markdown / MDX），以及由自己一磚一瓦搭建的介面與交互系統。在這裡，寫作不是一次性的情緒宣洩，而是知識與程式碼的持續重構。

## 2. 核心哲學：把博客當成長期維護的軟體工程

很多博客系統在建站完成的瞬間，就迎來了它生命周期的巔峰——隨後便陷入漫長的年久失修。而在 EpoCanvas 的設計哲學中：

> **博客不是一份靜態的 HTML 網頁，而是一套具備完整生命週期、持續演進的「軟體系統」。**

```
┌─────────────────────────────────────────────────────────────┐
│                   EpoCanvas 核心設計哲學                    │
├──────────────────────────────┬──────────────────────────────┤
│      1. 拒絕視覺噪聲         │      2. 堅持真實鏈路         │
│   技術感不等於滿屏霓虹光暈   │   全站指標真實掃描，零 Mock  │
│   在高資訊密度中保留閱讀秩序 │   每一篇字數與天數均有據可查 │
├──────────────────────────────┼──────────────────────────────┤
│      3. 規格化工程治理       │      4. 本地優先與邊緣計算   │
│   SemVer 版本、Git 追溯與 CI │   SSG 極速首屏 + 邊緣按需水合│
│   嚴格的單步 Commit 與 E2E   │   延遲壓制在 50ms 內的邊緣   │
└──────────────────────────────┴──────────────────────────────┘
```

### 2.1 技術感不等於噪聲：在高資訊密度中保留閱讀秩序
很多所謂的「極客風」主題，往往陷入炫技的誤區：到處是發光的賽博朋克邊框、粗糙的玻璃擬態、眼花繚亂的打字機動效。結果就是：**標題像按鈕、按鈕像裝飾、裝飾比正文內容更搶眼**。

我選擇了克制。我們保留了明確的網格、精準的狀態標籤與清晰的模塊邊界，但在排版上嚴格依循現代字體排印規範（Typography & Visual Hierarchy）：
- **主導航與水平展開子菜單**：向頂級博客體驗看齊，采用規整方圓角與居中吸附，杜絕跳躍與抖動；
- **文章閱讀節奏**：寬度舒適的文字閱讀欄、清晰的段落邊界、精細調校的程式碼高亮（Shiki）、平滑聚焦的粘性目錄（TOC）；
- **微交互反饋**：每一次按鈕懸浮、模態框呼出、暗色模式切換，均有細膩但絕不拖泥帶水的物理過渡。

### 2.2 堅持真實鏈路，杜絕任何虛假 Mock 數據
在 EpoCanvas 中，有一條寫入代碼守則的鋼鐵紅線：**嚴禁虛假數據**。
- 站點頂部的「全站字數」、「文章篇數」、「建站天數」，均由建置腳本實時遍歷全量 Markdown 檔案計算生成，並同步至生產節點；
- 評論系統完全基於 Cloudflare D1 雲原生數據庫，杜絕預先填寫的 Demo 虛擬發言；
- 贊賞記錄、支付狀態與 Telegram 機器人通知，均運行在端到端真實鏈路之上。

## 3. 架構演進：從 Hexo 到 Astro + Cloudflare 邊緣矩陣

EpoCanvas 的前身經歷了多次重構。每一次技術選型的遷移，都伴隨著對效能與開發體驗的深刻反思：

### 3.1 早期溯源：對 Hexo 與 Anzhiyu（安知鱼）經典設計的致敬
在專案初期，我們深度研究了 Hexo 生態中優秀的設計語言（特別是 Hexo-Theme-Anzhiyu 安知鱼主題）。其標誌性的頂部 Parallax 視差動態水波紋、水平排布的二級導航框、毛玻璃卡片以及充滿活力的作者卡片，給予了我豐富的介面美學靈感。

但隨著博客內容與交互複雜度的增長，傳統 Hexo 架構在現代前端工程面前暴露了局限：全量 JS 打包體積膨脹、缺乏元件化狀態管理、SSR/邊緣端擴展能力不足。

### 3.2 現代化重構：Astro 6 + React 19 + Tailwind 4 獨立島體系
為了兼顧「靜態內容的極致秒開」與「複雜應用的靈動交互」，我們在當前版本完成了全量重構：

1. **Astro Islands（獨立島架構）**：
   - 文章頁面、官方文件與歸檔總覽採用 **100% 零 JS 的純靜態 HTML 直出（SSG）**，首次加載零腳本負擔，Lighthouse 性能表現逼近滿分；
   - 僅在需要動態狀態的模塊（如 Stripe 國際收銀台、Telegram 翻轉卡片、中控台通知面板、動態星軌天文模擬引擎）中引入 React 19 進行**按需注水（Partial Hydration）**；
2. **現代化工程基礎設施**：
   - 採用 **Tailwind CSS 4** 進行底層設計 Token 約束，全域嚴格統一圓角（8px / 6px 方圓角）與主題色（`#425aef` 主題藍）；
   - 引入 **TypeScript** 實現端到端型別安全，所有導航、文章元數據與多語言配置均有強型別約束；
   - 內建 **Playwright / Puppeteer 現代自動化測試矩陣**，每次改動必須經受無頭瀏覽器的實機像素級與交互級驗收。

### 3.3 全球邊緣矩陣：Cloudflare Pages + Workers + D1
全站編譯產物直接託管於 Cloudflare 全球 Anycast 邊緣節點：
- 靜態資產全球 CDN 秒級命中，首字節時間（TTFB）普遍壓制在 50ms 以內；
- 動態 API（評論、按讚、支付會話、Telegram 廣播）運行在邊緣 Workers 執行時，與 Cloudflare D1 分散式資料庫無縫聯動。

## 6. 結語：保持生長，持續構建

> 「在不確定性的浪潮中，寫下確定性的邏輯。」

軟體會過期，框架會更迭，但經過深思熟慮的技術標準、優雅清晰的介面秩序，以及字裡行間對創作的真誠，能夠抵禦時間的沖刷。

EpoCanvas 將始終保持開放與生長。歡迎你在這裡漫步，也期待在程式碼與文字的交匯處，與你產生思想的共鳴。
