# EpoCanvas 贊賞、退款與第三方支付說明

> [!IMPORTANT]
> 支付頁面顯示的可用方式、幣種、費用與付款結果，會受到地區、裝置、瀏覽器、支付服務商、帳戶設定與網路狀態影響。請以付款介面最後顯示的內容與第三方服務紀錄為準；本站不承諾所有使用者都會看到相同的支付方式，也不承諾第三方服務持續可用。

## 1. 贊賞的性質與適用範圍

贊賞是讀者對內容維護、站點運作與創作工作的自願支持。它不會自動：

- 提升 `LV`、`TL`、角色或徽章；
- 解鎖受限文章、管理員功能、審核豁免或評論特權；
- 產生一份保證成功、保證即時通知或保證公開展示的服務合約；
- 使付款人取得 EpoCanvas 名稱、標誌、文章或其他內容的額外授權。

文章是否公開、是否存在訪問控制以及內容如何授權，應分別參考頁面本身與[內容授權與版權說明](/community/content-license/)。

## 2. 目前可見的支付通道

### 2.1 Stripe 結帳

本站的 Stripe 流程由 `/api/create-checkout-session` 建立 Checkout Session，並在瀏覽器中載入 Stripe 的結帳介面。程式碼目前配置了自動支付方式，因此在符合條件時可能出現：

- 一般信用卡或簽帳金融卡；
- Apple Pay、Google Pay 或 Link；
- Stripe 依帳戶、幣種、地區、裝置與風險判定提供的其他方式。

「可能出現」不是保證。Apple Pay/Google Pay 需要相容裝置、瀏覽器、錢包、卡片、網域驗證與支付商條件；如果快捷方式不可用，結帳介面可能改顯示一般卡片表單。

目前公開程式碼沒有獨立的 Stripe webhook 接收路由。付款完成後，前端完成回呼會進入 `/api/record-blessing`；服務端會用 Stripe API 再次核對 Session 或 PaymentIntent 的支付狀態，核驗成功後才可把記錄更新為可公開查詢的狀態。這與「Stripe webhook 即時送達」是不同的流程。

### 2.2 QR、PayPal 與 USDT

支援頁與文章內的贊賞元件可能依地區顯示微信支付、支付寶、PayPal 或 USDT 通道。這些通道具有不同的責任邊界：

| 通道 | 目前可確認的流程 | 重要限制 |
| :--- | :--- | :--- |
| 微信支付 / 支付寶 QR | 由第三方收款頁面或 QR 完成付款 | 本站沒有公開自動回調；若要加入名錄，需要提供必要交易資訊並由站方核對 |
| PayPal | 連往 PayPal 帳戶或顯示對應 QR | 費用、換匯、帳戶限制與爭議流程由 PayPal 規則決定 |
| USDT | 只在符合頁面地區與風險條件時顯示對應錢包/網路 | 鏈上轉帳可能不可逆；必須確認資產、網路、地址與手續費，本站不替錯誤轉帳恢復資產 |

第三方轉帳不會因為「已完成付款畫面」就自動成為本站的公開記錄。請保留交易時間、金額、幣種與必要的交易識別資訊，並以[檢舉與申訴說明](/community/reporting-and-appeals/)列出的聯絡方式私下詢問。

## 3. 幣種與金額

Stripe 支援頁目前提供「本地幣種」與「統一結算幣種」兩個選項。系統會先根據 Cloudflare 國家資訊或瀏覽器端的保守 fallback 推薦本地幣種；另一個選項目前通常是 USD，當本地選項本身是 USD 時則改用 HKD。

頁面上的檔位與自訂金額是本站配置的建議值，部分換算使用預設匯率與四捨五入規則，不是即時銀行報價，也不是對購買力、匯率或手續費的保證。實際扣款金額、幣種、發卡行換匯與額外費用，應以 Stripe、PayPal、發卡行或錢包在付款前顯示的結果為準。

請勿把卡號、卡片安全碼、密碼、一次性驗證碼或錢包私鑰填入稱呼、寄語、評論或聯絡信件。本站不需要這些資料來處理一般贊賞查詢。

## 4. 支援名錄的記錄生命週期

Stripe 記錄與公開名錄不是同一個狀態：

1. 建立 Checkout Session 或 PaymentIntent 時，系統可能先寫入內部的待確認記錄；這不代表付款已成功，也不會自動成為公開致謝；
2. 付款完成後，`/api/record-blessing` 會核對 Stripe 狀態；核驗失敗的請求不應建立公開贊賞記錄；
3. 支持者可在付款完成後提交稱呼與寄語。有效狀態可能包含 `completed`、`form_submitted`、`modal_closed`、`page_unload` 或 `idle_timeout_30m`，它們表示記錄流程的狀態，不是不同的付款金額；
4. `/api/sponsorships` 對外回應會遮蔽原始 IP、電子郵件、User-Agent、會話令牌與內部識別資訊，只輸出名錄需要的欄位；
5. QR、PayPal 或 USDT 的外部轉帳只有在站方核對並完成必要整理後，才可能被加入名錄。

頁面重新整理、網路中斷、關閉付款後表單或第三方服務延遲，都可能讓公開名錄晚於付款結果更新。名錄沒有顯示某筆記錄，不等於第三方付款一定失敗；請先以支付商的交易頁面或收據確認。

## 5. 通知、收據與資料公開

支付核驗與 Telegram 通知是兩條不同的鏈路。當部署環境配置了通知憑證時，站方可能在記錄流程中發送必要的摘要；通知失敗不會被解讀為付款失敗，也不代表每一則寄語必然在固定時間內被人工閱讀或回覆。

Stripe 是否寄送收據，取決於 Stripe 結帳時的電子郵件、帳戶與支付設定。本站不能代替 Stripe 保證收據必然寄達；若需要交易憑證，請先查閱 Stripe 的付款頁、電子郵件與帳戶紀錄。

公開名錄只應展示必要的稱呼、寄語、金額/幣種、通道與日期。後端仍可能為反濫用、交易核對、通知與安全審計保存國家、IP、支付狀態與時間欄位；相關資料邊界請同時參考[隱私與資料使用說明](/community/privacy-and-data/)。留空稱呼或寄語時，公開展示可能使用「匿名支持者」，但「匿名展示」不等於後端完全沒有交易或安全紀錄。

## 6. 退款、重複扣款與錯誤轉帳

目前專案沒有公開的自動退款 API，也沒有在頁面上承諾所有付款都能無條件全額退回。若遇到重複扣款、支付金額錯誤或需要查詢退款，請寄信至 [contact@epocanvas.com](mailto:contact@epocanvas.com)，並提供：

1. 支付通道與交易時間；
2. 幣種與金額；
3. Stripe Receipt、PaymentIntent/Checkout Session ID、PayPal 交易識別資訊或其他可定位資料；
4. 你希望更正、退款、匿名化或撤下公開展示的具體範圍。

站方會先核對交易與通道規則，再在可行範圍內處理。Stripe 退款須受 Stripe 帳戶、原路退回能力與支付爭議流程限制；QR 與 PayPal 受各自平台規則限制；鏈上轉帳則可能不可逆。本站不提供固定處理時限，也不要求你在公開評論中張貼交易憑證。

如果只是名錄中的稱呼、寄語或匿名設定需要更正，也請使用同一個聯絡入口。為防止冒領，站方可能要求原付款資訊或其他合理方式核對身份；已進入備份、審計或第三方服務的資料不一定能同步抹除所有副本。

## 7. 支付安全與第三方責任

本站會透過服務端密鑰、支付狀態核驗、輸入長度限制、公開欄位最小化與來源檢查降低風險，但不會把支付頁面描述成「絕對安全」「零手續費」或「永久可用」。

Stripe、PayPal、微信支付、支付寶、錢包服務、Cloudflare 與 Telegram 各自有服務條款、區域限制、資料處理方式與可用性邊界。使用第三方通道前，請閱讀其當前條款；任何通道名稱出現在本站，都不表示 EpoCanvas 能控制其審核、換匯、退款或爭議結果。
