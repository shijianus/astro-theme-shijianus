# EpoCanvas 無障礙與可及性說明

<div class="article-aside">
  <p><span class="badge badge-primary">COMMUNITY-012</span> <span class="badge badge-success">閱讀平等</span> <span class="badge badge-warning">持續改善</span></p>
  <p>本站把可及性視為內容與介面品質的一部分。這份說明列出目前的設計方向與回報方式，不宣稱所有頁面、第三方服務或歷史內容已完全符合任何單一標準。</p>

> [!NOTE]
> EpoCanvas 以 WCAG 2.2 AA 的可理解原則作為檢查參考，但實際體驗仍會受到瀏覽器、作業系統、輔助技術、第三方支付與動態內容影響。發現阻礙時，請提供可重現資訊，協助我們修正具體問題。

## 1. 我們維護的方向

官方頁面與互動元件應逐步朝以下方向維護：

- 使用有意義的標題階層、連結文字、表格標題與表單標籤，讓內容不依賴視覺位置才能理解；
- 讓主要閱讀、導覽、搜尋、帳號、評論與模態框流程可以透過鍵盤完成，並提供可辨識的焦點狀態與退出方式；
- 不只用顏色、圖示、動畫或聲音傳達必要資訊，並在狀態改變時提供文字或語義提示；
- 控制動畫、閃爍、浮動層與自動播放內容的干擾，尊重使用者的減少動態偏好；
- 讓文字、程式碼、引用、表格、圖片與錯誤訊息在不同視窗大小與縮放比例下仍可閱讀；
- 為由讀者或作者提供的圖片、圖表與嵌入內容保留替代文字、來源或必要的上下文。

這些是維護要求與驗收方向，不是對每一個既有元件已完成的保證。若目前實作與本文方向有差異，應在問題追蹤中標記範圍與優先級。

## 2. 內容作者與貢獻者的責任

提交文章、政策修訂或評論時，請：

1. 使用清楚的標題、段落與列表，不用連續空格或純裝飾符號模擬版面；
2. 為有資訊意義的圖片提供簡短、準確的替代文字，裝飾性圖片不要把無關內容寫入替代文字；
3. 表格包含可理解的欄位標題，程式碼區塊標示語言並在正文解釋其目的；
4. 不以「點擊這裡」「看上面顏色」作為唯一指示，連結文字應能單獨說明目的；
5. 避免未說明的自動播放、快速閃爍、過度依賴 Emoji 或只面向滑鼠的互動；
6. 引用第三方圖片、圖表、字型或嵌入內容時，同時確認授權與可及性限制。

## 3. 已知限制與優先處理

動態評論、登入、支付、站內搜尋、控制台與第三方嵌入可能有不同的焦點、錯誤提示、讀屏順序或載入狀態。若某個互動流程無法使用，請先記錄：

- 頁面網址與具體操作位置；
- 瀏覽器、作業系統、螢幕尺寸與縮放比例；
- 使用的輔助技術或鍵盤操作方式（如適用）；
- 預期結果、實際結果與可重現步驟；
- 是否為每次發生，或只在登入、深色模式、行動版等條件下發生。

不要為了證明問題而提交真實帳號密碼、會話令牌、醫療/身份資料或其他敏感內容。

## 4. 回報與修正流程

一般可及性問題可以寄至 [contact@epocanvas.com](mailto:contact@epocanvas.com)，主旨標示「[無障礙]」，也可以依[貢獻與官方文件編輯規範](/community/contributing-and-editorial/)提交可重現的修訂建議。若問題同時涉及帳號、個資或安全風險，請改依[安全問題通報規範](/community/security-disclosure/)私下處理。

維護者會依影響範圍、是否阻斷核心功能、受影響的使用者與修正風險安排處理。修正後應以鍵盤、至少一種主流瀏覽器與適合的響應式視窗重新檢查；若涉及讀屏或特定輔助技術，應在條件允許時補做相應驗證。

## 5. 第三方內容的邊界

Cloudflare、Stripe、Epomail、Telegram、影片、地圖、支付按鈕或其他外部內容可能有自己的無障礙能力與限制。本站會在整合層提供必要的替代說明與錯誤邊界，但不能替第三方服務保證完整符合性。遇到第三方介面本身的障礙時，也可以在回報中標記供應商與具體元件。
