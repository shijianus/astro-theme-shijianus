# EpoCanvas 評論與審核規範

<div class="article-aside">
  <p><span class="badge badge-primary">COMMUNITY-002</span> <span class="badge badge-success">評論系統</span> <span class="badge badge-warning">以伺服器規則為準</span></p>
  <p>本頁整理留言系統目前已實作的公開行為與限制。它補充《社群公約》，不取代公約中的安全、尊重與權利要求。</p>
</div>

> [!NOTE]
> 評論功能仍在持續演進。若介面提示、本文與伺服器回應不一致，生產環境的伺服器驗證結果優先；已知的前端與後端字數差異會在本文明確標示，待後續統一。

## 1. 可以發表什麼

評論系統支援以下互動形式：

| 類型 | 用途 | 目前限制 |
| :--- | :--- | :--- |
| 一般評論 | 對文章提出觀點、補充、提問或錯誤回報 | 前端輸入上限目前為 500 字；後端仍接受至多 1000 字，兩者待統一 |
| 回覆 | 在既有評論下進行分層討論，也可引用留言 | 仍受一般評論限流與內容審核規則約束 |
| `Boost` | 對其他讀者的留言快速鼓勵或短回覆 | 最多 16 字；應在回覆既有留言時使用 |
| `Reaction` | 對既有留言表示支持或情緒反應 | 需要登入；同一登入使用者對同一留言維持一個有效反應，可取消或切換 |

評論可以包含受控的 Markdown 標記，例如粗體、引用、程式碼、表格、數學式、劇透與提示區塊。連結與檔案上傳不屬於目前公開工具列的預設功能；請勿用留言繞過這項限制散播外部引流或檔案。

## 2. 排序、狀態與公開呈現

- 評論流支援「最新」與「最熱」排序；最熱排序會參考 Reaction/Like 數量，置頂內容優先。
- 公開介面不顯示其他讀者的電子郵件、原始 IP、User-Agent 或會話令牌。
- 目前可見的資料狀態包含 `published`、`pinned`、`flagged` 與 `deleted`；`deleted` 不會出現在一般公開評論流，其他狀態由站務流程依需要呈現或處理。
- 回覆、引用與多層巢狀內容仍必須遵守同一篇文章的語境與《社群公約》。
- 留言作者可以在有效的當前會話中就地編輯或刪除自己的內容；訪客會話在重新整理、切換瀏覽器或失去原有會話後可能無法再證明所有權。

## 3. 限流與反濫用

以下是生產環境目前由伺服器依 IP、內容類型與身份執行的一小時窗口限制：

| 身份 | 一般評論 | `Boost` |
| :--- | ---: | ---: |
| 訪客 | 3 次 / 小時 | 5 次 / 小時 |
| 已登入讀者 | 30 次 / 小時 | 50 次 / 小時 |

此外，同一 IP 在一小時內重複提交完全相同的內容會被攔截。這些限制是保護討論品質與服務可用性的措施，不代表內容已通過審核；通過限流也不代表內容一定公開。

開發環境可能使用本地記憶體或落盤資料，且可能不套用完整生產限流，因此不能用本地測試結果推斷線上配額。站務與安全必要的內部操作不應被解讀為一般讀者的公開配額。

## 4. 身份、地區與 Reaction 權限

- 未登入訪客可以在允許的範圍內發表一般評論與回覆，但不能對留言按讚或使用 Reaction。帳號與會話的身份、令牌及所有權邊界，另見[帳號與會話安全說明](/community/account-and-session/)。
- 登入讀者可以使用 Reaction；若選擇不同 Emoji，系統會切換自己的反應，選擇相同 Emoji 則可取消。
- 訪客的國家或地區會依請求中的 Cloudflare 國家資訊公開顯示旗幟與地區名稱；這是評論公開規則的一部分。
- 登入讀者可以選擇是否公開自己的地區；隱藏時，公開介面不應向其他讀者顯示該地區。
- 管理員在具備有效管理權限時，才能查看更完整的審計欄位；這不等於一般讀者可以查詢他人的私密資料。

## 5. 審核原則

站方會按照《社群公約》判斷內容，並視風險採取提醒、標記、限制、下架或停權。審核會特別留意：

1. 人身攻擊、歧視、威脅、騷擾與未經同意的私人資料；
2. 垃圾內容、重複貼文、惡意刷量、機器人或規避限流；
3. 釣魚、詐騙、惡意程式碼、危險指引與未揭露的外部追蹤；
4. 著作權、商標、肖像與其他第三方權利爭議；
5. 蓄意把技術討論帶離原文語境，造成持續干擾或圍攻。

站方不承諾每則留言都會即時人工審核，也不承諾所有爭議都能在公開頁面完整還原。遇到高風險內容時，可能先限制可見性，再透過審核與申訴流程補充處理。若內容涉及越權、個資外洩或惡意程式，請依[安全問題通報規範](/community/security-disclosure/)私下通報。

## 6. 已知差異與修訂要求

目前程式碼存在兩個需要後續收斂的公開契約差異：

- 前端輸入元件將一般評論限制為 500 字，後端 API 的一般評論驗證上限為 1000 字；對外使用時請以 500 字作為保守上限。
- 客戶端 `src/lib/user-level.ts`、服務端 `functions/_lib/auth-service.ts` 與登入身份資料的等級映射並非同一套計算；評論權限不應以某一個本地顯示的 LV/TL 數字推論。

這些差異應在實作統一後更新本頁與相關測試；在此之前，伺服器驗證、帳號實際權限與站務處置結果優先。
