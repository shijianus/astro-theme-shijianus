# 这是一篇受保护的文章

如果你在未解锁状态下直接查看这篇文章，下面这些正文不会被服务端输出到页面里，而不是简单地先输出再用前端隐藏。

## 解锁后你应该验证什么

1. 未输入密码时，正文不会出现在 HTML 里。
2. 输入正确密码 `12345` 后，服务端会写入短时访问凭证。
3. 再次刷新当前文章时，不需要重复输入密码。
4. 首页卡片、最新文章和摘要不会泄露受保护正文。

## 这层规则目前支持什么

- 密码访问
- 指定 IP 可见
- 指定 IP 不可见
- 指定国家或地区可见
- 指定国家或地区不可见

## Frontmatter 写法示例

下面这几段写法都可以直接放进文章 frontmatter：

```yaml
access:
  passwordHash: "5994471abb01112afcc18159f6cc74b4f511b99806da59b3caf5a9c173cacfc5"
  message: "输入正确密码后继续阅读。"
```

```yaml
access:
  blockedCountries: ["CN"]
  message: "当前地区不可访问这篇文章。"
```

```yaml
access:
  allowedIps: ["203.0.113.7", "198.51.100.*", "192.0.2.0/24"]
  message: "当前网络地址不在允许范围内。"
```

如果你只想允许某一个国家或地区访问，也可以直接写：

```yaml
access:
  allowedCountries: ["US", "GB", "HK"]
```

## 为什么推荐使用 passwordHash

虽然当前仍兼容直接写 `password`，但更推荐在 Markdown 里只写 `passwordHash`。这样主题只会在服务端做比对，不需要把明文密码保存在内容配置中。

如果你需要自己生成哈希值，当前主题内部使用的是 `SHA-256`。推荐在本地先把密码转成哈希，再写入 frontmatter，而不是把明文密码直接放进文章源文件。

## 为什么这层不会把受限正文提前漏出去

这套实现不是“先把全文输出，再靠前端隐藏”。受限文章页面走的是服务端判定：

1. 未满足密码或地区/IP 规则时，服务端只返回锁定面板。
2. 正文、目录、相关文章和公开摘要都不会在未解锁时渲染进页面。
3. 首页、分页、最新文章、搜索索引和侧栏也不会把受限文章混进去。

## 结论

这篇文章主要是给你后续做烟测用的。只要锁定页、解锁页、刷新后的保留状态都正常，就说明这套访问控制已经从“概念功能”进入了可实际使用的状态。
