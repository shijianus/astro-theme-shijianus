# 首页是入口，不是仓库

很多博客主题会在首页一次性塞入所有能力，看起来功能很多，但读者很难判断先读什么。

## 我对首页的拆法

新的首页分成四段：

1. 顶部 hero 和品牌语义
2. 分类入口和状态卡
3. 文章流
4. 侧栏的作者与索引能力

## 为什么这样更耐用

因为以后增加新能力时，只需要判断它属于哪一层，而不是再临时找地方塞进去。

## 对未来 API 的帮助

当首页层级稳定之后，即使以后接入：

- 热门文章
- 访问统计
- 实时状态

这些数据也只是在既有位置替换内容，而不会破坏整体视觉秩序。
